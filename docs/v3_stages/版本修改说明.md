# v3-stages-r1：从矩阵QoS实验适配到逐调用三阶段预测

## 解决的问题
原脚本只使用第一版WS-DREAM扰动矩阵、按服务索引取固定实体属性，不能处理v3同一服务多次调用时的状态变化；缺少独立验证选模和三阶段整合。

## 改动
新增experiments/v3_stages独立入口：冻结仿真代码副本提供机理参考；prepare.py生成逐调用缓存；modeling.py实现连续/类别输入、基础AFIL、实体融合和MLP；train.py只读取训练/验证；select.py选择验证最优固定方案；evaluate.py冻结后评价；verify_results.py独立复算；run_server.sh检查GPU并按顺序执行。
默认不使用用户/服务/设备ID嵌入；共享QKV交互与旧AFIL保持一致。执行公式保留；就绪方法通过验证选取。原生成数据和旧训练脚本均未修改。

## 已完成验证
1449个源文件哈希一致；144803条训练、48243条验证；运行隔离、主键唯一、阶段加和和执行公式一致。AFIL五种输入设置CPU前向反向通过。GPU1完成门控AFIL两轮技术试跑并成功保存/重载检查点。试跑使用旧兼容环境，不算正式对照结果。

## 当前状态
用户已要求继续执行，复查空闲后已在GPU0（RTX5880）正式训练。新环境PyTorch 2.7.1+cu128及数据处理依赖已安装并通过数据与模型验收。完整候选、消融及冻结测试正在依次执行，最终结论以完成后的结果报告为准。

## 复现与结果
服务器工作目录/data/qops_lxy_20261118，数据和结果不入Git。执行入口：bash code/run_server.sh <GPU编号或两个逗号分隔编号>。不得使用已有计算进程的卡。首次正式运行将搜索预先登记的候选，运行期间不读取测试指标进行选择。

## v3-stages-r2：补齐身份对照与可观测训练过程

解决的问题：旧AFIL含用户和服务身份，单独采用无身份基线可能高估实体上下文提升；新环境缺少numpy等依赖；缺少用户能直接查看的训练进度。

修改位置：modeling.py增加世界内用户/服务身份编码和未知类别；orchestrate.py增加三组身份控制；select.py用验证较强基础对照评估目标；evaluate.py同步消融命名、设备等权偏差和产物冻结；train.py增加逐轮训练MAE；monitor.py提供只读实时窗口；predict.py提供仅输入快照的完整推理；report.py汇总冻结结果；保存环境依赖。

验证：全部十种AFIL输入设置前后向通过；原始1449文件哈希、运行隔离、公式与标签加和再次通过。新增对照在首次测试评价前确定；已完成的无身份实验保留。训练与验证预测已能保存并重载检查点。

## 调度更新
在同一张GPU0上采用最多两个独立训练进程，提高小模型实验吞吐；每项训练的配置保持不变。orchestrate.py记录execution_schedule，run_server.sh传入并行数。已完成任务跳过，切换时等待已有训练完成。没有使用额外显卡。
